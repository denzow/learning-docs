# 第1章 演習問題

対象章：[第1章 データモデリングの全体像](../01-overview.md)（[読み上げ原稿](../audio-scripts/01-overview.md)）

## 問題

### 問1

業務部門の担当者を交えたレビューで合意を取るために、注文業務のデータモデルを一枚描くことになった。
この場面で用意するモデルとして適切なものはどれか。

- A. 各テーブルの主キーと外部キー、正規化の度合いまで確定させた図
- B. 実装先の DBMS で使うデータ型とインデックスを注記した図
- C. 業務上の関心事とそのつながりだけを、実装から独立した業務の言葉で表した図
- D. 実行可能な DDL と、それを図に起こした ER 図の組

### 問2

データモデルを概念、論理、物理の三つのレベルに分けて管理する利点はどれか。

- A. レベルごとに変更の理由と頻度が異なるため、実装環境を乗り換えるときの作り直しを下位のレベルだけに閉じ込められる
- B. 抽象度の高いモデルから順に機械的に変換できるため、設計の工数を減らせる
- C. 業務部門、設計者、DBA という担当ごとに成果物の所有権を切り分けられる
- D. 一枚の図に詳細を詰め込まずに済み、モデルの見た目の複雑さを抑えられる

### 問3

オンラインストアの注文明細テーブルに、書籍マスタの定価とは別に販売時点の単価を持たせることにした。
この決定を物理モデルではなく論理モデルの段階で下すのはなぜか。

- A. 列の追加はストレージ使用量を増やし、性能とコストに影響するから
- B. 明細テーブルの主キーの構成を変える必要があるから
- C. 正規化の原則から外れる設計は、DBMS を確定させてからでないと判断できないから
- D. 定価が改定された後も過去の注文金額を再現するという業務上の要請であり、採用する DBMS には依存しないから

### 問4

OLTP システムのテーブル設計では、冗長を排除する方向（正規化）が選ばれる。
その理由はどれか。

- A. テーブルを分割すると、問い合わせを並列に処理しやすくなるから
- B. 同じ事実を複数の場所に持つと、高頻度の書き込みの中で一部だけ更新される不整合が起きるから
- C. 正規化されたテーブルのほうが、大量の行を集計する処理に向いているから
- D. データ量を減らして、ストレージのコストを抑えることが主目的だから

### 問5

DWH の集計用テーブルでは、書籍タイトルのような属性を明細行ごとに複製して持つ設計が採られる。
OLTP なら避けるべきこの冗長が、DWH では問題になりにくいのはなぜか。

- A. このテーブルは直接書き換えず、元データから定期的に作り直すため、複製の間の矛盾が生じにくいから
- B. DWH 製品は一意制約を持たず、冗長なデータを検出しないから
- C. 分析の問い合わせは読み取り専用であり、データに矛盾があっても集計結果には影響しないから
- D. 列指向ストレージが重複する値を自動的に一つへまとめて保存するから

## 解答と解説

### 問1

**解答**：C

概念モデルの読み手には業務側の関係者が含まれるため、データ型やキーを持たず、エンティティと関係を業務の言葉だけで表す。
A は属性やキーまで決める論理モデル、B と D は特定の DBMS 上の実装を表す物理モデルの成果物であり、業務側とのレビューには詳細が多すぎる。
「三つの抽象レベル」の節で述べた、図一枚で業務の構造に合意するという概念モデルの目的に対応する問題である。

### 問2

**解答**：A

業務の構造は製品を乗り換えても変わらないが、物理的な実装は DBMS の変更やデータ量の増加で作り直しになる。
変わる速度と理由が違うものを別のレベルに分けておけば、DWH を別製品へ移行するときも物理モデルだけを設計し直せば済む。
B のような機械的な変換や C のような担当の切り分けは章ではレベル分けの根拠とされておらず、D の見た目の複雑さも本質的な理由ではない。

### 問3

**解答**：D

注文時点の販売価格を明細側に記録しておかなければ、定価の改定後に過去の注文金額を再現できなくなる。
これは業務の要請から来る判断であり、どの DBMS を使うかに関係しないため、論理モデルの段階で決める。
A のような性能とコストに関わる決定こそが物理モデルの担当であり、置き場所の判断基準が逆になっている点で誤りである。

### 問4

**解答**：B

OLTP には少数の行を特定して読み書きする処理が高い頻度で届くため、同じ事実を二か所に持つと片方だけ更新される更新異常が起きる。
正規化はこの不整合を構造の側で防ぐための設計方針である。
C はむしろ逆で、大量の行を集計する処理に向くのは非正規化した OLAP 側の構造であり、D のストレージ節約も正規化の主目的ではない。

### 問5

**解答**：A

DWH の集計用テーブルは利用者が直接書き換える対象ではなく、元データから定期的に作り直されるため、複製に起因する矛盾が入り込みにくい。
加えて列指向ストレージは問い合わせに必要な列だけを読むので、列を複製しても集計のコストはほとんど増えない。
C は誤りで、矛盾したデータを集計すれば結果も誤る（読み取り専用であることは矛盾の無害化にはならない）。
D の言う重複値の自動的な統合は、複製を許せる理由として章が挙げた内容ではない。

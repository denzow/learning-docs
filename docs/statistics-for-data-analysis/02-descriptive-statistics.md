# 第2章 記述統計と分布の要約

「先月の注文金額の平均は 3,200 円だった」という報告は、12,000 件の注文を一つの数に圧縮している。
圧縮である以上、何かを捨てている。
捨てたものが問いにとって重要でなければ、その要約はよい要約であり、重要なものを捨てていれば、正確に計算された数であっても読み手を誤らせる。
第 1 章で分けた記述統計と推測統計のうち、本章は前者、手元のデータをどう要約するかを扱う。

要約の善し悪しは、要約する前の全体の姿、すなわち分布の形によって決まる。
そこで本章は、分布を見るところから始め、代表値、散らばり、パーセンタイルと外れ値、対数変換、集計の粒度の順に、要約の道具とその選び方を解説する。
題材は書籍オンラインストアの注文金額で、右に長く裾を引く分布の典型である。
この形は、以降の章で推定や検定の前提を考えるときにも繰り返し現れる。

## 概念の解説

### 分布と度数分布表

一つの変数が取る値と、それぞれの値がどれだけの頻度で現れるかの対応を、その変数の**分布**と呼ぶ。
注文金額なら、300 円の注文が何件、1,500 円の注文が何件、というすべての対応が分布である。
要約の対象は個々の注文ではなく、この分布である。

分布を最初に見る道具が**度数分布表**である。
値の範囲を等間隔の区間（階級）に区切り、各区間に入る件数（度数）と、全体に占める割合を並べる。
度数分布表を棒の高さで描いたものが**ヒストグラム**で、分布の形を一目で読める。
形を見るときの観点は三つある。
山が一つか複数か、山が中央にあるか一方に寄っているか、そして裾がどちらへどれだけ長く伸びているかである。

山が左に寄り右に長い裾を引く形を**右に歪んだ分布**（正の歪み）と呼ぶ。
金額、所要時間、アクセス数のように、下限がゼロで上限のない量の多くはこの形になる。
注文金額もそうで、文庫本一冊の 1,500 円前後に山があり、まとめ買いや高額の専門書が右の裾を作る。
逆に左に長い裾を引く形が左に歪んだ分布で、満点近くに集中するテストの点数などがその例である。
以降で述べる要約の道具の使い分けは、ほぼすべてこの歪みの有無から導かれる。

### 代表値：平均、中央値、最頻値

分布の中心を一つの数で表したものを**代表値**と呼び、代表的な三つが平均、中央値、最頻値である。

**平均**は、値の合計を件数で割った数である。
合計と件数から計算できるため、SQL の集計として最も安価であり、売上のように合計そのものに関心がある問いでは自然な代表値になる。
平均に件数を掛ければ合計に戻るという性質は、他の二つにはない。

**中央値**は、値を小さい順に並べたときに中央に来る値である。
件数が偶数なら中央の二つの平均を取る。
半分の注文は中央値より安く、半分は高い、という位置の情報であり、個々の値の大きさには影響されない。
一件の極端な注文があっても、順位が一つずれるだけで中央値はほとんど動かない。

**最頻値**は、最も頻度の高い値である。
連続的な量では同じ値が繰り返し現れることが少ないため、度数分布表で最も度数の高い階級として読む。
質的な変数（第 1 章の名義尺度）では、平均も中央値も定義できないので、最頻値が唯一の代表値になる。

三つの使い分けは分布の形で決まる。
左右対称な分布では三つがほぼ一致し、どれを使っても同じ話になる。
右に歪んだ分布では、最頻値、中央値、平均の順に右へずれる。
裾の少数の大きな値が合計を押し上げるため、平均だけが裾の側へ引っ張られるからである。
注文金額では最頻値が 1,500 円付近、中央値が 2,400 円、平均が 3,200 円と、三つの値がはっきり分かれる。
このとき「平均的な注文」という言い方は誤解を招く。
実際、平均の 3,200 円を下回る注文は全体の 65% にのぼり、平均は大多数の注文よりも高い金額を指している。
典型的な一件の姿を伝えたいなら中央値を、合計に結びつけたいなら平均を選び、歪んだ分布では両方を並べて報告する。

### 散らばり：分散、標準偏差、変動係数

代表値だけでは、値がその周りにどれだけ集中しているかがわからない。
中心からの離れ方を一つの数で表したものが散らばりの指標である。

**分散**は、各値と平均との差（偏差）を二乗して平均した数である[^ddof]。
偏差をそのまま平均すると正負が打ち消し合ってゼロになるため、二乗して符号を消す。
その代償として、分散の単位は元の単位の二乗（円²）になり、そのままでは読めない。
分散の正の平方根を取って単位を元に戻したものが**標準偏差**である。
注文金額の標準偏差は 2,800 円で、これは「典型的な注文は平均から 2,800 円くらい離れている」と読める。

標準偏差を「平均 ± 標準偏差の範囲に約 68% の値が入る」と読む説明をよく見かける。
この読み方は分布が正規分布に近いときに限って成り立つ（第 3 章）。
右に歪んだ注文金額では、平均 − 標準偏差は 400 円で分布の左端近くまで届く一方、平均 + 標準偏差の 6,000 円より右にはまだ 10% 以上の注文が残る。
歪んだ分布では、標準偏差は散らばりの大きさの目安にはなっても、範囲の目安にはならない。

単位の違う量の散らばりを比べるには、標準偏差を平均で割った**変動係数**を使う。
日次の注文数（平均 400 件、標準偏差 60 件）と注文金額（平均 3,200 円、標準偏差 2,800 円）の散らばりは、円と件では比べられないが、変動係数なら 0.15 と 0.9 として比べられる。
注文数は日によって 15% 程度しか揺れないのに対し、一件の注文金額は平均と同じくらいの幅で揺れる、という比較ができる。
ただし変動係数は、平均がゼロに近い量や負の値を取る量には使えない。

### パーセンタイル、四分位範囲、箱ひげ図

値を小さい順に並べたとき、下から p% の位置にある値を **p パーセンタイル**と呼ぶ。
中央値は 50 パーセンタイルである。
25、50、75 パーセンタイルを順に**第 1 四分位数**、第 2 四分位数、**第 3 四分位数**と呼び、第 3 四分位数から第 1 四分位数を引いた幅を**四分位範囲**（IQR）と呼ぶ。
四分位範囲は中央の 50% の注文が収まる幅であり、標準偏差と違って裾の極端な値に影響されない。

最小値、第 1 四分位数、中央値、第 3 四分位数、最大値の五つを**五数要約**と呼び、これを図にしたものが**箱ひげ図**である[^tukey]。
箱が四分位範囲、箱の中の線が中央値を表す。
ひげは、箱の両端から四分位範囲の 1.5 倍以内にある最も遠い値まで伸ばし、その外側の値は点として個別に描く。
この「四分位範囲の 1.5 倍」を外れ値の目安とする規則が広く使われている。

注文金額でこの規則を適用すると、第 3 四分位数 3,930 円に四分位範囲 2,500 円の 1.5 倍を足した 7,680 円が上側の境界になり、全注文の 6% がその外に出る。
一か月で 750 件である。
これらは入力誤りでも異常でもなく、専門書のまとめ買いという通常の注文である。
この規則は左右対称な分布を想定して作られており、右に歪んだ分布では裾の正当な値を大量に外れ値の側に振り分けてしまう。
箱ひげ図の点を機械的に外れ値と呼ぶわけにはいかない。

### 外れ値の扱い

他の値から極端に離れた値を**外れ値**と呼ぶ。
前節の規則が示すように、外れ値かどうかは値だけでは決まらず、その値がどこから来たかの判断を伴う。
判断の軸は、外れ値の由来である。

- **記録の誤り**：単位の取り違え、テストデータの混入、二重登録など。データそのものが事実を表していないので、原因を特定して除外するか修正する。
- **別の母集団の混入**：法人の一括購入や社内の検証注文のように、分析したい対象とは別の集団から来た値。除外するかどうかは問いによる。個人客の購買行動を知りたいなら除外し、売上全体を知りたいなら含める。
- **正当な極端値**：分析対象の集団に属し、単にまれに起きる大きな値。除外する理由はない。要約の側を、平均ではなく中央値やパーセンタイルのような極端値に影響されにくい統計量に切り替える。

由来にかかわらず、値を除外したり修正したりしたときは、何件をどの基準で扱ったかを結果とともに記録する。
除外の基準を変えれば平均は動くので、基準が記録されていない要約は再現できない。
極端値の影響を抑えたいが除外もしたくない場合には、上位 1% の値を 99 パーセンタイルの値で置き換える打ち切り（ウィンザー化）や、上位 1% を外して平均を取る刈り込み平均もある。
これらは平均と中央値の中間の性質を持つ折衷案であり、使ったなら明記する。

### 対数変換

右に歪んだ量は、対数を取ると左右対称に近い形になることが多い。
対数は掛け算を足し算に変える変換であり、1,000 円から 2,000 円への変化と 5,000 円から 10,000 円への変化を、どちらも「2 倍」として同じ幅に写す。
金額のように比率で変化する量は、対数の尺度で見たほうが分布の形が素直になる。
注文金額の対数を取ると、山は中央に来て、平均 ± 標準偏差の範囲に約 68% が収まる形になる。

対数の尺度で計算した平均を元の尺度に戻す（指数を取る）と、平均ではなく**幾何平均**になる。
幾何平均は算術平均より小さく、右に歪んだ分布では中央値に近い値になる。
注文金額では、対数の平均を元に戻すと 2,380 円で、中央値の 2,400 円とほぼ一致し、算術平均の 3,200 円とは離れる。
対数変換した後の平均を元の単位に戻して「平均金額」と報告すると、合計と整合しない数を平均と呼ぶことになる。
対数の尺度で比較した差は、元の尺度では倍率の違いとして解釈する。

対数変換は要約のためだけの道具ではない。
第 3 章で扱う対数正規分布は「対数を取ると正規分布になる分布」であり、第 6 章の t 検定や第 7 章の回帰でも、歪んだ量を対数に変換してから扱うことが多い。

### 集計の粒度

同じ「平均注文金額」でも、何を一件として数えるかで値が変わる。
注文を一件として数えれば、注文の多い顧客の注文がその件数分だけ平均に効く。
顧客を一件として数え、顧客ごとの平均を求めてからさらに平均すれば、注文の多い顧客も少ない顧客も一人として同じ重みで効く。

三人の顧客を考える。
一人は 5,000 円の注文を 10 回、残りの二人は 2,000 円の注文を 1 回ずつ行った。
注文単位の平均は 54,000 円 ÷ 12 件で 4,500 円、顧客単位の平均は (5,000 + 2,000 + 2,000) ÷ 3 で 3,000 円である。
どちらが正しいかは問いで決まる。
「一回の注文で平均いくら売れるか」なら注文単位、「顧客一人あたりの購買の典型」なら顧客単位である。
分析基盤のテーブルは注文や明細のような細かい粒度で持たれていることが多く、何も考えずに集計すると注文単位の平均になる。
報告する数がどの粒度の平均かは、数値と一緒に書く。

## 具体例

書籍オンラインストアの先月の注文 12,000 件（一日およそ 400 件）を対象に、分布を見てから要約し、外れ値と粒度の影響を確かめる。
テーブルは分析基盤のマートにある orders（order_id、customer_id、ordered_at、device、amount）である。

### 度数分布表を SQL で作る

要約の前に分布の形を見る。
注文金額を 1,000 円刻みの階級に区切り、階級ごとの件数と割合を求める。
10,000 円以上は件数が少ないので一つにまとめる。

```sql
WITH binned AS (
    SELECT
        LEAST(FLOOR(amount / 1000) * 1000, 10000) AS bin_start
    FROM orders
    WHERE ordered_at >= DATE '2026-08-01'
      AND ordered_at <  DATE '2026-09-01'
)
SELECT
    bin_start,
    COUNT(*) AS order_count,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS pct
FROM binned
GROUP BY bin_start
ORDER BY bin_start;
```

結果を度数分布表として並べると次のようになる。

| 階級（円） | 件数 | 割合（%） |
| --- | --- | --- |
| 0 〜 999 | 1,521 | 12.7 |
| 1,000 〜 1,999 | 3,356 | 28.0 |
| 2,000 〜 2,999 | 2,579 | 21.5 |
| 3,000 〜 3,999 | 1,625 | 13.5 |
| 4,000 〜 4,999 | 929 | 7.7 |
| 5,000 〜 5,999 | 637 | 5.3 |
| 6,000 〜 6,999 | 385 | 3.2 |
| 7,000 〜 7,999 | 284 | 2.4 |
| 8,000 〜 8,999 | 184 | 1.5 |
| 9,000 〜 9,999 | 134 | 1.1 |
| 10,000 以上 | 366 | 3.0 |

山は 1,000 円台にあり、そこから右へ長く裾が伸びる。
2,000 円未満の注文が全体の 4 割を占める一方、10,000 円以上の注文も 3% ある。
右に歪んだ分布だとわかった時点で、平均だけで要約しない方針が決まる。

### 代表値と散らばりを SQL で求める

平均、標準偏差、五数要約を一度の問い合わせで求める。
パーセンタイルは、多くの DWH で PERCENTILE_CONT のような順序集計関数として書ける[^percentile]。

```sql
SELECT
    COUNT(*)                                            AS order_count,
    ROUND(AVG(amount))                                  AS mean_amount,
    ROUND(STDDEV_SAMP(amount))                          AS sd_amount,
    MIN(amount)                                         AS min_amount,
    PERCENTILE_CONT(0.25) WITHIN GROUP (ORDER BY amount) AS q1,
    PERCENTILE_CONT(0.50) WITHIN GROUP (ORDER BY amount) AS median_amount,
    PERCENTILE_CONT(0.75) WITHIN GROUP (ORDER BY amount) AS q3,
    PERCENTILE_CONT(0.90) WITHIN GROUP (ORDER BY amount) AS p90,
    PERCENTILE_CONT(0.99) WITHIN GROUP (ORDER BY amount) AS p99,
    MAX(amount)                                         AS max_amount
FROM orders
WHERE ordered_at >= DATE '2026-08-01'
  AND ordered_at <  DATE '2026-09-01';
```

```text
order_count  mean_amount  sd_amount  min_amount  q1    median_amount  q3    p90   p99    max_amount
12000        3200         2800       300         1430  2400           3930  6300  14300  55940
```

平均 3,200 円に対して中央値は 2,400 円で、平均が右の裾に引かれている。
中央の 50% の注文は 1,430 円から 3,930 円の幅に収まるが、上位 1% は 14,300 円を超え、最大は 56,000 円近い。
変動係数は 2,800 ÷ 3,200 で約 0.9 になる。

同じ要約は pandas でも一行で得られる。
分析基盤から取り出した注文金額を DataFrame に載せて describe を呼ぶと、件数、平均、標準偏差、最小値、四分位数、最大値が並ぶ。

```python
import numpy as np
import pandas as pd

orders = pd.read_sql(
    "SELECT amount FROM orders WHERE ordered_at >= '2026-08-01' AND ordered_at < '2026-09-01'",
    conn,
)
print(orders["amount"].describe(percentiles=[0.25, 0.5, 0.75, 0.9, 0.99]).round())
# count    12000
# mean      3200
# std       2800
# min        300
# 25%       1430
# 50%       2400
# 75%       3930
# 90%       6300
# 99%      14300
# max      55940

log_amount = np.log(orders["amount"])
print(np.exp(log_amount.mean()).round())   # 2380（幾何平均。中央値に近い）
print(orders["amount"].skew().round(2))     # 3.62（右に歪んでいる）
print(log_amount.skew().round(2))           # 0.04（対数を取るとほぼ対称）
```

歪度（skew）は分布の非対称の度合いを表す数で、対称なら 0、右に歪むほど正の大きな値になる。
対数を取ると歪度が 3.6 から 0.04 まで下がり、対数の尺度では左右対称に近いことが確かめられる。
幾何平均の 2,380 円が中央値とほぼ一致することも、この対称性の帰結である。

### 一件の大口注文が平均に与える影響

ある日の注文 400 件の平均が 3,470 円、中央値が 2,530 円だったとする。
この日に、法人から 500,000 円の一括注文が一件加わった。

```python
day = orders_of_the_day["amount"]            # 400 件
with_bulk = pd.concat([day, pd.Series([500_000])])

print(day.mean().round(), day.median())              # 3470  2530
print(with_bulk.mean().round(), with_bulk.median())  # 4710  2530
print(day.std().round(), with_bulk.std().round())    # 3050  24980
```

一件の注文で平均は 1,240 円上がり、標準偏差は 8 倍になる。
中央値は動かない。
個人客の購買行動を追う日次の指標として平均を使っていれば、この日は施策と無関係に跳ね上がり、翌日には元に戻る。
この注文は記録の誤りではないので、直すべきはデータではなく要約の側である。
個人客の行動を見る指標には中央値か、法人注文を除外した平均を使い、法人注文は件数と金額を別に報告する。

### 注文単位と顧客単位の平均

分析基盤のテーブルから、二つの粒度の平均を求める。
注文単位の平均は AVG 一つで求まるが、顧客単位の平均は先に顧客ごとに集計してから平均する二段階になる。

```sql
WITH per_customer AS (
    SELECT
        customer_id,
        COUNT(*)    AS order_count,
        AVG(amount) AS avg_amount
    FROM orders
    WHERE ordered_at >= DATE '2026-08-01'
      AND ordered_at <  DATE '2026-09-01'
    GROUP BY customer_id
)
SELECT
    ROUND(SUM(avg_amount * order_count) / SUM(order_count)) AS mean_per_order,
    ROUND(AVG(avg_amount))                                  AS mean_per_customer,
    ROUND(AVG(order_count), 2)                              AS orders_per_customer
FROM per_customer;
```

```text
mean_per_order  mean_per_customer  orders_per_customer
3200            2950               1.33
```

注文単位の平均のほうが 250 円高い。
月に何度も注文する顧客は一件あたりの金額も大きい傾向があり、その顧客の注文が件数分だけ注文単位の平均に効くからである。
ダッシュボードの「平均注文金額」がどちらを指すかは、定義を確かめないとわからない。
指標の名前には粒度を含めるか（「注文あたり平均金額」「顧客あたり平均金額」）、定義を指標の説明に書く。

[^ddof]: 手元のデータを標本と見て母集団の分散を推定するときは、偏差の二乗の合計を件数 n ではなく n − 1 で割る（不偏分散）。SQL の STDDEV_SAMP や pandas の std はこの n − 1 で割る定義を使い、numpy の std は既定で n で割る。件数が数千あれば両者の差は無視できるが、ライブラリによって既定が違う点は覚えておく。

[^tukey]: 箱ひげ図と五数要約は、Tukey が探索的データ解析の道具として 1977 年に提案した。四分位範囲の 1.5 倍という係数も Tukey の提案で、理論的な根拠があるというより経験的な目安である。

[^percentile]: PERCENTILE_CONT は SQL 標準の順序集計関数だが、製品によっては APPROX_QUANTILES や PERCENTILE_APPROX のような近似関数しか提供しないものや、WITHIN GROUP を伴わない構文のものがある。近似関数は大規模なデータでも一度の走査で計算できる代わりに、結果が厳密なパーセンタイルと僅かにずれる。

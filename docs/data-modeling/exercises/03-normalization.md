# 第3章 演習問題

対象章：[第3章 正規化](../03-normalization.md)（[読み上げ原稿](../audio-scripts/03-normalization.md)）

## 問題

### 問1

修正異常や挿入異常や削除異常が起きるテーブルには、共通する構造上の原因がある。
その原因として正しいものはどれか。

- A. 主キーや外部キーの制約を宣言し忘れており、不正な書き込みを検査できていないから
- B. 一つの行が、発生や変更のタイミングの異なる複数の事実を一緒に運んでいるから
- C. 複数の画面やバッチ処理が同じテーブルに同時に書き込み、更新が競合するから
- D. テーブルを細かく分割しすぎて、結合のたびに整合を取り直す必要が生じるから

### 問2

注文明細テーブルには、注文時点の販売価格を表す列と、書籍の定価を表す列がある。
関数従属の観点からこの二つの列を説明した記述として、正しいものはどれか。

- A. どちらも書籍の価格に関する情報だから、両方とも書籍 ID に従属する
- B. 販売価格は書籍 ID に従属し、定価は明細のキー全体に従属する
- C. 手元のデータで両者の値が常に一致しているなら、一つの列にまとめて片方に従属させてよい
- D. 販売価格は明細のキー全体に、定価は書籍 ID に従属し、どちらに矢印を引くかは業務ルールで決まる

### 問3

第3正規形を満たしているのに BCNF に違反するテーブルが見つかった。
このテーブルの扱いについて、正しい記述はどれか。

- A. BCNF に分解すると元の候補キーの一意性を制約として宣言できなくなる場合があり、あえて第3正規形にとどめて検査で補う判断もありうる
- B. BCNF は第3正規形より条件が緩いため、第3正規形を満たしていれば分解を検討する必要はない
- C. この違反は、非キー属性が別の非キー属性を経由して候補キーに従属していることを意味する
- D. この形は理論上の存在であり、実務のテーブルに現れることはないため無視してよい

### 問4

書籍ごとに販売地域が複数あり、販売フォーマットも複数あるため、書籍 ID と地域とフォーマットの 3 列を持つテーブルに全組合せの行を並べている。
このテーブルを地域のテーブルとフォーマットのテーブルに分けるべきかどうかの判断として、正しいものはどれか。

- A. 全組合せの行を並べるテーブルは冗長だから、業務の内容によらず常に二つに分けるべきである
- B. 主キーが全属性の組になっているテーブルは第4正規形を満たすため、分ける必要はない
- C. 地域とフォーマットが業務ルールとして互いに独立に決まる場合に限り分けるのが正しく、地域ごとに販売フォーマットが決まる業務なら 3 列のまま持つのが正しい
- D. 現在のデータに全組合せが実際に並んでいるかどうかを集計し、並んでいれば分けると決めればよい

### 問5

DWH の変換パイプラインが作る結合済みテーブルは、意図的に正規形を崩した設計の典型とされる。
このようなテーブルで非正規化が許容しやすい理由として、正しいものはどれか。

- A. DWH では行の追加しか行わないため、更新異常が原理的に発生しないから
- B. 書き込み経路が変換処理の一つに限られて毎回作り直され、利用が読み取り中心で、崩した従属の破れを検査に翻訳できるから
- C. 分析用途では多少の矛盾が混入しても集計結果への影響が小さく、許容できるから
- D. 列指向ストレージが重複した値を自動的に圧縮するため、冗長を持つコストが消えるから

## 解答と解説

### 問1

**解答**：B

章の冒頭で述べたとおり、三種の異常の原因は行の単位と事実の単位のずれにある。
一つの行が複数の事実を運ぶと、事実ごとに発生と変更と消滅のタイミングが違うため、重複と欠落が避けられない。
A が誤りなのは、重複した記録どうしの一致を宣言する標準的な制約はそもそも存在せず、制約の宣言漏れの問題ではないからである。
C は同時実行制御の話題であり、テーブル構造に由来する更新異常とは別の問題である。

### 問2

**解答**：D

具体例の「関数従属の洗い出し」で扱った論点である。
販売価格は注文時点の明細の事実だからキー全体に従属し、定価は書籍の事実だから書籍 ID に従属する。
C が誤りなのは、関数従属が業務ルールの写しだからである。
いまのデータでたまたま値が一致していることは、業務ルールとして常に成り立つことを意味せず、正規化の根拠にならない。

### 問3

**解答**：A

BCNF への分解では、違反する従属を別テーブルに移した結果、元の候補キーがどのテーブルにも収まらず、一意性制約を宣言できなくなる場合がある（従属性の保存の破れ）。
このため、分解して失った制約を検査で補うか、違反を承知で第3正規形にとどめて破れを監視するかの比較判断が要る。
B は逆で、BCNF は第3正規形の見逃し（候補キーを構成する属性への従属）を塞ぐ、より厳しい条件である。
C は第3正規形が禁じる推移的関数従属の説明であり、第3正規形を満たすテーブルには当てはまらない。
D も誤りで、担当者と領域のような割り当てを扱う業務では珍しくない形である。

### 問4

**解答**：C

第4正規形の分解が正しいのは、二つの多値の事実が業務ルールとして独立な場合だけである。
地域ごとにフォーマットが決まるなら多値従属は成立せず、3 列のテーブルこそが正しい構造になる。
A が誤りなのはこの条件を無視しているからであり、D が誤りなのは、多値従属も関数従属と同じく業務ルールの写しであって、データの形から判定するものではないからである。

### 問5

**解答**：B

非正規化の判断基準の節で挙げた三つの条件（書き込み経路の制御、読み取りの支配、検査の設置可能性）を、変換パイプラインの派生テーブルは典型的に満たす。
混入した矛盾は次の再生成で消え、崩した正規形が分かっていれば破れうる従属を検査に翻訳できる。
A が誤りなのは、更新異常が起きなくなるのではなく、起きても管理できる条件がそろっているだけだからである。
C も誤りで、章の立場は矛盾の許容ではなく、検査による検出である。
